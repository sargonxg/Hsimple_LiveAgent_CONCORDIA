# CONCORDIA — Complete Google Cloud Shell Deployment Guide

This guide covers every step to deploy CONCORDIA from a clean Google Cloud account using only the browser-based Cloud Shell — no local tools required.

---

## What You'll Deploy

A fully working AI mediation system with:
- **Live real-time conversation** via Gemini Live API (voice + text)
- **TACITUS conflict ontology** — 8 primitives automatically extracted during conversation
- **D3 network graph** visualizing actors, claims, interests, leverage, and relationships
- **11 conflict resolution theories** auto-matched to each case
- **Common ground proposals** generated by the resolver agent
- **Demo mode** — works without an API key for evaluation

---

## Prerequisites

| Requirement | How to get it |
|-------------|---------------|
| Google Cloud account | https://cloud.google.com (free tier works) |
| GCP project with billing enabled | Cloud Console → Billing |
| Gemini API key | https://aistudio.google.com → "Get API Key" |

> **Gemini Live API**: Uses `gemini-2.0-flash-live-001`. If you don't have access yet, use the text-only fallback: `MODEL=gemini-2.0-flash-exp` (see Step 4B).

## Step 1 — Open Google Cloud Shell

1. Go to https://shell.cloud.google.com
2. Sign in with your Google account
3. Wait for the shell to initialize (takes ~30 seconds)
4. You'll see a terminal prompt: `username@cloudshell:~`

---

## Step 2 — Set Your GCP Project

```bash
# Check your current project
gcloud config get-value project

# If not set, list available projects
gcloud projects list

# Set your project
gcloud config set project YOUR_PROJECT_ID
```

> Replace `YOUR_PROJECT_ID` with your actual project ID (e.g. `my-mediation-app-123`).

## Step 4A — Deploy (with Gemini Live API — recommended)

```bash
# Set your Gemini API key from https://aistudio.google.com
export GOOGLE_API_KEY="AIzaSy..."

# Run the one-command deployment script
bash deploy_cloudshell.sh
```

This script:
1. Enables Cloud Run, Cloud Build, and Container Registry APIs
2. Builds your Docker container using Cloud Build (no local Docker needed)
3. Deploys to Cloud Run with session affinity (required for WebSocket) and 1-hour timeout
4. Prints your live URL

**Takes approximately 4–6 minutes on first deploy.**

## Step 6 — Open the App

1. Click the URL printed in the terminal (or open it in a new tab)
2. The CONCORDIA interface loads — dark theme, 3-panel layout

### If you have an API key:
1. Enter your Gemini API key in the **top-left** "Gemini API Key" box → click **Set**
2. Click **⚡** (Connect) in the chat area
3. Choose Party 1 or Party 2 from the selector
4. Start speaking or typing — the agent introduces itself and begins the mediation

### If you want to explore without an API key:
1. Click the **"Demo"** button next to the connect button
2. A pre-built lease dispute scenario loads with full graph, theories, and conversation history
3. Use the right-side tabs to explore: **Actors**, **Graph**, **Theories**, **Resolve**

---

## Step 7 — Run a Full Mediation Session

### Party 1 Session
1. Select **Party 1** in the "Speaking As" panel
2. Click **⚡ Connect**
3. Party 1 speaks naturally. The agent listens and silently builds the conflict graph
4. Watch the health bar — it shows readiness for resolution (75% threshold)
5. Upload documents: drag-drop a contract, email, or letter for automatic extraction

### Party 2 Session
1. Select **Party 2**
2. Click **⚡ Connect** (a new session is created — Party 2's context is separate)
3. The agent says "I have some background" but reveals nothing from Party 1
4. Party 2's perspective is added to the shared graph

### Resolution
1. Open the **Resolve** tab → click **"Analyze Common Ground"**
2. When graph health ≥ 75%, the agent automatically transfers to `resolver_agent`
3. The resolver proposes 2–3 concrete resolution paths with:
   - What each party gets and gives up
   - ZOPA (Zone of Possible Agreement) analysis
   - Implementation steps and verification milestones

## Configuration Options

### Change Mediator Style
```bash
curl -X POST https://YOUR-URL/api/configure \
  -H "Content-Type: application/json" \
  -d '{"mediator_style": "analytical", "case_type": "commercial", "objective": "Settle contract dispute by Friday"}'
```

Available styles: `empathetic`, `analytical`, `directive`, `transformative`, `narrative`, `facilitative`, `evaluative`, `restorative`

Available case types: `workplace`, `family`, `commercial`, `community`, `geopolitical`

### Set Mediation Objective
```bash
curl -X POST https://YOUR-URL/api/set-objective \
  -H "Content-Type: application/json" \
  -d '{"objective": "Reach lease termination agreement preserving both parties reputations"}'
```

### Load Demo Scenario (Programmatically)
```bash
curl -X POST https://YOUR-URL/api/load-demo
# Returns: complete conflict graph with 3 actors, 6 claims, 6 interests, 5 constraints, 4 leverage points, 2 broken commitments, 5 events, 2 narratives
```

### Reset Graph
```bash
curl -X POST https://YOUR-URL/api/reset \
  -H "Content-Type: application/json" \
  -d '{"keep_config": true}'
```

## Using Vertex AI Instead of Google AI Studio

For production deployments using your GCP project's Vertex AI:

```bash
# Enable Vertex AI
gcloud services enable aiplatform.googleapis.com

# Deploy with Vertex AI config (no GOOGLE_API_KEY needed)
gcloud run deploy concordia \
  --source . \
  --region us-central1 \
  --allow-unauthenticated \
  --timeout 3600 \
  --session-affinity \
  --memory 1Gi \
  --set-env-vars "GOOGLE_GENAI_USE_VERTEXAI=TRUE,GOOGLE_CLOUD_PROJECT=YOUR_PROJECT_ID,GOOGLE_CLOUD_LOCATION=us-central1,CONCORDIA_MODEL=gemini-2.0-flash-live-001"
```

Grant the Cloud Run service account Vertex AI access:
```bash
PROJECT_NUMBER=$(gcloud projects describe YOUR_PROJECT_ID --format='value(projectNumber)')
gcloud projects add-iam-policy-binding YOUR_PROJECT_ID \
  --member="serviceAccount:${PROJECT_NUMBER}-compute@developer.gserviceaccount.com" \
  --role="roles/aiplatform.user"
```

```bash
  --role="roles/secretmanager.secretAccessor"

# Redeploy with secret reference

  --region us-central1 \
  --update-secrets="GOOGLE_API_KEY=gemini-api-key:latest"
```

## Troubleshooting

### "Error: failed to build" during deploy
```bash
# Check Cloud Build logs
gcloud builds list --limit=5
gcloud builds log LAST_BUILD_ID
```

Most common cause: missing `requirements.txt`. Verify you're in the `concordia/` directory.

### WebSocket connection fails
Cloud Run requires `--session-affinity` and `--timeout 3600` for WebSocket sessions. Verify:
```bash
gcloud run services describe concordia --region us-central1 | grep -E "timeout|session"
```

If missing, redeploy with the full `deploy_cloudshell.sh` script.

### "quota_exhausted" error in chat
Gemini Live API has separate rate limits from standard Gemini. Options:
1. Wait 60 seconds and retry
2. Switch to text-only model: `curl -X POST https://YOUR-URL/api/configure -d '{"mediator_style":"analytical","case_type":"workplace"}'` and redeploy with `MODEL=gemini-2.0-flash-exp`

### Audio not working in browser
- Audio requires HTTPS (Cloud Run provides this automatically)
- Check browser microphone permissions (address bar → lock icon → microphone)
- Only `*-live-*` models support audio; text-only models (`gemini-2.0-flash-exp`) output text only

### Agent not extracting graph data
If the graph stays empty after conversation:
- Check the chat for purple tool-call pills — if none appear, the agent isn't recognizing extraction triggers
- Be more specific: "My name is Maria Chen, I'm a tenant" triggers `add_actor`; "They owe me $3,200" triggers `add_claim`
- Upload a document: drag-drop a text file into the upload area for bulk extraction

### Demo button shows error
The demo requires the server to be running. The `/api/load-demo` endpoint is a POST with no body. Test directly:
```bash
curl -X POST https://YOUR-URL/api/load-demo
```

## Architecture Summary

```
Browser (index.html)
    │
    ├── REST (/api/*) ──────────────────► FastAPI (main.py)
    │                                         │
    └── WebSocket (/ws/{party}/{session}) ─► ADK Runner
                                              │
                                    concordia (root agent)
                                         └── listener_agent  [11 build tools]
                                               └── verifier_agent  [6 analysis tools]
                                                     └── resolver_agent  [6 resolution tools]
                                                              │
                                                    ConflictGraph (in-memory)
                                                    8 TACITUS primitives:
                                                    Actor, Claim, Interest, Constraint,
                                                    Leverage, Commitment, Event, Narrative
```

All agents use `gemini-2.0-flash-live-001` (or fallback model) via Google ADK's `Runner.run_live()`.
The conflict graph is shared state — all agents read/write the same `ConflictGraph` object.
Party isolation: each node has `contributed_by` field; the listener never reveals Party 2's data to Party 1.
